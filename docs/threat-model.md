# Znimok — модель загроз

> Статус: **чернетка v0.1 (28.09.2026, ZK-84)** — для рецензії власником. Опирається на PLAN §5.5–5.10,
> рішення в `decisions.md` і прототипи P1–P4. Переглядати перед кожним мажорним релізом і коли з'являється
> нова точка входу (новий формат, мережевий виклик, інтеграція).
>
> *English summary:* Znimok is a per-user desktop app with no network access by default. The assets are
> what is on the user's screen and in their library; the main risks are untrusted files, AI agents over-reaching
> (including prompt injection through screen content), secrets leaking in shared screenshots, and a tampered
> update. The table in §5 lists each threat with its mitigation, the ticket that implements it and the risk left.

## 1. Що захищаємо і від кого

Znimok робить знімки й записи екрана, редагує їх і віддає далі — людям (буфер, файл, «Поділитися») і
AI-агентам (MCP, «Передати агенту», помічник Ctrl+K). Усе працює на пристрої користувача, від його імені,
**без прав адміністратора** (`asInvoker`, per-user інсталяція) і **без мережі за замовчуванням**: мережа —
лише перевірка оновлень і явні дії користувача (власний ключ API, згодом — цілі поширення).

Припущення:

- ОС і обліковий запис користувача не скомпрометовані; антивірус і оновлення ОС — справа ОС.
- Програма, що працює від того самого користувача, має ті самі права на файли, що й Znimok. Від неї
  повністю не захиститися (див. §7), але Znimok не повинен **додавати** їй можливостей: відкритих портів,
  безмовного доступу до екрана, ключів у відкритому вигляді.
- Користувач довіряє собі, але не завжди пам'ятає, що на екрані: секрети в кадр потрапляють випадково.

## 2. Активи

| Актив | Де живе | Чому цінний |
|---|---|---|
| Вміст екрана в момент знімка | пам'ять процесу, кадр захоплення | паролі, токени, листування, обличчя, персональні дані |
| Бібліотека: `.znimok`, PNG/JPEG/WebP, MP4, `.zreport` (v2) | тека бібліотеки (може бути на хмарному диску) | те саме + історія роботи; звіти містять лог DevTools (URL, запити, помилки) |
| Метадані документа | блоки `META`/`DESC`, EXIF/iTXt при експорті | ім'я автора, назва вікна, програма, дата |
| Буфер обміну | ОС (на Windows — ще й історія Win+V) | останній знімок, файл |
| Ключ API моделі (BYOK) | Windows Credential Manager / macOS Keychain | гроші користувача, доступ до його акаунта |
| Ключі й дозволи агентів | профіль Znimok | хто може знімати екран без питання |
| Журнал дій агентів і помічника | профіль, 90 днів, без зображень | що і коли знімалось / відправлялось |
| Канал оновлень і ключ підпису релізів | GitHub Releases; приватний ключ — секрет CI | підміна оновлення = виконання коду на всіх машинах |
| Налаштування | JSON у теці конфігу | гарячі клавіші, тека бібліотеки, режими хмари |
| Крах-дампи | локальна тека | можуть містити фрагменти пам'яті з пікселями |
| Увага й довіра користувача | — | індикатори запису/агента мають бути правдою |

## 3. Межі довіри і точки входу

```
 ┌────────────── пристрій користувача, один обліковий запис ─────────────────────────────┐
 │                                                                                         │
 │  ОС: захоплення (WGC/DXGI, ScreenCaptureKit), буфер, файли, гарячі клавіші, трей       │
 │         │                                                                               │
 │  ┌──────▼───────────────── процес Znimok ───────────────────────────┐                   │
 │  │ накладка / редактор / бібліотека / шар команд / парсери файлів   │◄── файли, DnD,    │
 │  │ помічник Ctrl+K     IPC-сервер (pipe / unix socket, токен)       │    Ctrl+V         │
 │  └──────┬──────────────────────┬─────────────────────┬──────────────┘                   │
 │         │ MCP stdio / IPC       │ Native Messaging    │ провайдер мініатюр (COM DLL      │
 │  ┌──────▼──────┐        ┌───────▼────────┐            │ у процесі Провідника) / Quick Look│
 │  │ агенти (MCP)│        │ розширення (v2)│            │ appex — ті самі парсери          │
 │  └─────────────┘        └────────────────┘                                              │
 └─────────┬───────────────────────────────────────────┬───────────────────────────────────┘
           │ HTTPS: перевірка оновлень (GitHub)          │ HTTPS: хмарна модель (лише з ключем
           ▼                                              ▼ користувача й за його дією)
```

Точки входу, що приймають **недовірені дані**:

1. Файли: `.znimok`, зображення (PNG, JPEG, WebP, GIF, BMP; HEIC/AVIF — через декодери ОС), `.zreport` (v2),
   перетягування, вставка з буфера.
2. Провайдер мініатюр Windows (`IThumbnailProvider`) і Quick Look на macOS — розбирають `.znimok` у
   **чужому процесі** (Провідник / Finder) щойно файл з'являється в теці.
3. IPC і MCP: запити агентів (JSON-RPC), зокрема тексти, які агент отримав з інтернету чи з екрана.
4. Вміст екрана, що йде агентам і помічнику: пікселі й розпізнаний текст можуть містити **інструкції для
   моделі** (prompt injection).
5. Відповіді хмарної моделі помічника (план команд).
6. Розширення браузера (v2): події DevTools зі сторінки.
7. Оновлення: маніфест і пакет з GitHub Releases.
8. Залежності й CI (ланцюг постачання).

## 4. Хто може нашкодити

| Діяч | Можливості | Мета |
|---|---|---|
| Відправник файла | дає `.znimok`, картинку чи звіт (лист, чат, завантаження) | збій, виконання коду, вичерпання пам'яті |
| Скомпрометований або надто ретельний агент | виклики MCP у межах дозволів | зняти більше, ніж потрібно; вивести дані |
| Автор вмісту на екрані | текст/картинка у вікні, яке знімають | prompt injection: змусити агента чи помічника діяти |
| Мережевий нападник | між програмою і GitHub / API моделі | підмінити оновлення, підслухати |
| Ланцюг постачання | шкідливий крейт, зламаний CI, викрадений ключ підпису | код у релізі |
| Інша програма того самого користувача | читає файли, буфер, під'єднується до IPC | отримати знімки, ключ, дозволи |
| Сторонні люди | бачать екран, отримують поширений знімок | секрети в картинці, метадані |

## 6. Правила для розробки, що випливають із моделі

1. Жодних відкритих мережевих портів. IPC — лише pipe / unix socket з правами поточного користувача.
2. Будь-який новий мережевий виклик — окремий пункт у політиці приватності й перемикач у налаштуваннях
   «Приватність» (сторінка вже перелічує все, що торкається мережі).
3. Кожен новий парсер (формат, імпорт) — з межами розмірів і fuzz-ціллю в тому ж PR.
4. Ключі й токени — лише в системному сховищі; ніколи не логувати аргументи, що можуть їх містити.
5. Агент і помічник — лише через шар команд; нових «обхідних» API для них не робити.
6. Індикатори (запис, агент, хмара) — не можна вимкнути налаштуванням.
7. Зміни, що зачіпають §3 (нова точка входу), — перегляд цієї моделі в тому ж PR.

## 7. Поза межами і свідомі компроміси

- **Шкідлива програма від того самого користувача** може прочитати теку бібліотеки, токен IPC з профілю
  і, на Windows, облікові дані з Credential Manager. Знімок екрана вона може зробити й без Znimok.
  Znimok лише не полегшує їй роботу (немає портів, немає безмовних дозволів, ключ не в файлі).
- Фізичний доступ до розблокованого комп'ютера, скомпрометована ОС, шкідливі драйвери.
- Поведінка зовнішніх агентів після того, як вони отримали дані за дозволом, і політика хмарного
  провайдера моделі — поза контролем Znimok; користувач бачить, що і кому передано (журнал, прев'ю).
- Шифрування бібліотеки: не робиться, щоб файли лишались звичайними файлами (мініатюри, пошук,
  хмарні диски). Для чутливих даних — шифрування диска засобами ОС.
