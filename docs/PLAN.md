# Znimok — план розробки (результат ZK-1)

Складено 27.09.2026 сесією Claude Fable 5.1 за підсумками дослідження (тека `docs/discovery/`:
інвентаризація коду Little Helpers у трьох файлах `inventory_*.md` і три дослідження стану
бібліотек `research_*.md`) та восьми кіл питань власнику. Документ має два рівні: розділи 1–4
для власника (без технічних деталей), розділи 5–12 для агентів, що реалізовуватимуть план.

---

## 1. Що будуємо (коротко для власника)

**Znimok** — окрема програма для Windows 11 і macOS 15+, яка робить знімки екрана та запис
відео, редагує їх і допомагає ділитися. Головне вікно — редактор із бібліотекою і
налаштуваннями всередині; у треї (на Mac у menu bar) живе лише маленький помічник для
запуску знімка чи запису. Файли між Windows і Mac переносяться без втрат. Програма не
вимагає прав адміністратора, нікуди не дзвонить без явної дії людини, а всі її можливості
однаково доступні людині й AI-агентам.

**Перший реліз (v1.0)** — знімки: захоплення, редактор, бібліотека, поширення (PNG, буфер
обміну, системне меню «Поділитися»), MCP для агентів, дві AI-функції («передати агенту»,
розумне маскування секретів) і помічник природною мовою. **Другий реліз (v2.0)** — запис
відео і редактор відео, лог DevTools і звіт для розробника. Далі — інтеграції зі Slack, Jira,
Telegram, Redmine, хмарні посилання, власна синхронізація, камера й автозум.

**Стек:** Rust. Інтерфейс на Slint із власним стилем, однаковим на обох ОС. Полотно редактора
малюється рендерером Vello у текстуру wgpu; текст — стеком Parley із вбудованими
шрифтами. Захоплення й кодування — рідні API кожної ОС (Windows Graphics Capture і Media
Foundation; ScreenCaptureKit і VideoToolbox). Прототипи Фази 1 підтвердили Slint і Vello
(звіт — [PROTOTYPES.md](PROTOTYPES.md), 29.09.2026).

**Ліцензія й розповсюдження:** як у Little Helpers — код публічний для аудиту, перевикористання
заборонене; безкоштовно, без реклами, з донатами; архітектура допускає платні надбудови
пізніше. Підпис і нотаризація — коли з'являться сертифікати (Apple 99 $/рік, Certum ≈ 139 €/рік);
до того — розробка і тестові збірки.

**Терміни (орієнтовно, залежать від темпу перевірок власником і доступу до Mac):**

| Етап | Зміст | Орієнтовно |
|---|---|---|
| Фаза 1 | прототипи зняття ризиків | 3–4 тижні |
| Фази 2–3 | фундамент, захоплення знімків на обох ОС | 5–6 тижнів |
| Фаза 4 | редактор | 6–8 тижнів |
| Фази 5–7 | поширення, агенти, системна інтеграція, інсталятори, реліз v1.0 | 7–9 тижнів |
| **Разом до v1.0** | | **≈ 5–7 місяців** |
| Фаза 8 | відео, реліз v2.0 | +4–5 місяців |

## 3. Інвентар: що переноситься з Little Helpers

Повні таблиці — `discovery/inventory_screenshots.md`, `inventory_video.md`, `inventory_system.md`.
Класи: **A** — алгоритм або модель даних, переноситься майже 1:1; **B** — логіка та сама, пишеться
заново поверх нового рендера/інтерфейсу; **C** — окремий бекенд на кожну ОС; **D** — не переносимо.

| Область | Рядків C++ | Клас | Що беремо |
|---|---|---|---|
| Модель позначок (`EdObj`, 10 видів), виділення, групи, вирівнювання, влучання, ручки | ≈2 200 | A | Структури й правила дослівно: лічильник не зберігає номера; група — спільний номер, не контейнер; кадр — властивість, не обрізання; тон і поворот — рецепт поверх оригіналу; банки пікселів за номерами |

## 5. Архітектура

### 5.1 Принципи

- **Один процес, готовий до поділу.** Фонова частина (клавіші, накладка, захоплення, запис)
  і редактор — один процес, але спілкуються лише через шар команд і черги; жодного спільного
  змінного стану між ними. Поділ на два процеси = замінити транспорт команд на IPC, який і
  так існує для агентів.
- **Стан → рендер**, а не «повідомлення → змінити глобальну змінну → перемалювати вікно».
- **Одна модель документа для знімків і відео** (як у LH: позначка має кадри `[vf0, vf1)`).
- **Один шар команд** обслуговує GUI, CLI, MCP, помічника на моделі й тести.
- **Файл — джерело правди**, індекси перебудовуються.
- **Мінімальні привілеї, нуль мережі за замовчуванням.**

### 5.3 Модель документа (`znimok-core`)

```rust
pub struct Document {
    pub id: Uuid,                    // сталий id, переживає перейменування і синхронізацію
    pub kind: DocKind,               // Image | Video (v2)
    pub meta: Meta,                  // created (UTC), name, source, desc, author, copyright, tags
    pub source: SourceId,            // поточний оригінал у банку (незмінний; зміна розміру = новий)
    pub banks: Banks,                // оригінали й вкладені зображення, адресуються номерами
    pub recipe: Recipe,              // exposure ±2.0 EV, gamma 0.5–2.0, contrast ±50, rot (чверті), mirror
    pub crop: Option<IRect>,         // кадр — властивість, не обрізання пікселів
    pub shot_scale: u16,             // DPI монітора зйомки ×1000 (радіуси кутів)
    pub counters: CounterState,      // seq, start, group, next_group
    pub objects: Vec<Object>,        // z-порядок = індекс
    pub group_names: BTreeMap<GroupId, String>,
    pub video: Option<VideoDoc>,     // v2: частини таймлайну, in/out, геометрія, доріжки
}

pub struct Object {
    pub kind: ObjectKind,            // Rect | Ellipse | Line | Pen | Text | Hide | Mark | Counter | Stamp | Image
    pub rect: IRect,                 // координати зображення; для Line знак w/h — напрямок
    pub style: Style,                // color, thick, alpha, no_main, color2/alpha2, dash, corners, shadow, glow
    pub rot: u16, pub group: GroupId, pub name: Option<String>, pub hidden: bool,
    pub frames: Option<(u32, u32)>,  // v2: [vf0, vf1)
    pub data: ObjectData,            // типізовані поля виду: Text{text,size,bold,italic,align,boxw},
                                     // Hide{mode,strength}, Counter{seq,group,start,shape}, Line{heads},
                                     // Pen{points}, Stamp{id}, Image{bank_id}
}
```

Правила з LH переносяться дослівно (див. `inventory_screenshots.md` §2, §7 п.19–47). Undo — знімки
стану `Snapshot { objects, selection, crop, recipe, source, group_names }` глибиною 120 з тими ж
правилами злиття серій. Пікселі живуть у банках і в знімки не копіюються.

### 5.4 Шар команд і запитів

Кожна дія — значення `Command` (serde, версійована схема JSON), кожне читання — `Query`:

```
Command: Capture{target: Screen|Window{id}|Region{rect}|Interactive, dest: Editor|Clipboard|Overlay|File}
         AddObject, UpdateObject, DeleteObjects, Select, Group, Ungroup, Align, Distribute, Raise,
         SetCrop, SetRecipe, Rotate, Mirror, ResizeImage, ResizeCanvas, Undo, Redo,
         Save, SaveCopy, Export{format, path|clipboard}, Share{target}, OpenPath, Import,
         Library{Rename, Delete, Restore}, Settings{Set}, Agent{Grant, Revoke}, ...
Query:   ListDisplays, ListWindows (id, title, app, bounds у координатах екрана й знімка),
         GetDocument, GetSelection, LibraryList{filter}, GetSettings, GetState, Ocr{doc|rect}, ...
```

Обробник команд — один (`znimok-core::apply`), результат — подія `Changed{...}`, на яку реагує
UI. Через нього ж працюють: GUI, `znimok` CLI, MCP-інструменти, помічник на моделі, e2e-тести.
Це відповідь на вимогу 10 (agent adoption в обидва боки) і заміна тестових хуків LH штатним API.

### 5.5 Формат `.znimok` (v1.0)

За принципами `.lhshot`, але без сумісності з ним (`docs/FORMAT.md` пишеться у Фазі 2):

- Шапка: магія `ZNIMOK\x1A\n` (8 байт), `u16 major = 1`, `u16 minor = 0`; читач відкидає `major > 1`,
  `minor` не перевіряє. Файл упізнається за магією, не за розширенням. Спадкових полів LH
  (`fill`, `outl`, COLORREF) немає — формат проєктується з чистого аркуша.
- Блоки `tag[4] + u32 len + вміст`, порядок байтів явно little-endian; невідомі блоки й поля
  пропускаються за довжиною; рядок = `u32` довжина + UTF-8; кольори — `RGBA8`; час — i64 мс епохи UTC.
- Блоки v1: `META` (uuid, created, name, source, версія програми), `DESC`, `INFO` (w, h, кількість,
  тип документа), `THMB` (PNG ≤ 320×240 зведеного кадру), `SRC ` (PNG оригіналу), `BANK`, `RCPE`,
  `CROP`, `SCAL`, `NUMS`, `OBJS` (об'єкт = `OBJ ` + поля-TLV, вид — текстовим тегом), `GRPN`, `FONT`
  (список використаних вбудованих шрифтів за іменем і версією). Метаблоки — до `SRC `, щоб
  бібліотека читала лише шапку.
- Нові поля — лише коли не типові; атомарний запис `.part` → rename; межі читача як у LH.
- v2 додає блоки відео (`CUTS`, `GEOM`, `MOUS`, `DEVT`, аудіодоріжки) без зміни major.
- Розширення: `.znimok` (v1); питання одного чи двох розширень — на етапі відео (рішення 28).
- Звіт для розробника (v2): `.zreport` = ZIP без стиснення (як `.lhreport`) або один HTML ≤ 100 МБ.
- Сумісності з файлами Little Helpers немає (рішення 29). Власний `.zreport` відкривається в редакторі (v2).

### 5.6 Бібліотека і синхронізація

- Тека користувача (`%LOCALAPPDATA%\Znimok\Library`, `~/Library/Application Support/Znimok/Library`),
  змінювана в налаштуваннях (щоб покласти на iCloud/OneDrive/NAS). Файли — джерело правди.
- Індекс `redb` у теці кешу: uuid, назва, дата, розмір, мініатюра з `THMB`, хеш; перебудова при
  розбіжності; спостерігач файлової системи (`notify`) для зовнішніх змін.
- Ім'я файлу — штамп часу, назва документа в `META` (перейменування не чіпає файл). Конфлікти
  хмарних дисків («copy 2») розпізнаються за uuid.
- Майбутня власна синхронізація спирається на uuid + версію документа в `META`.

### 5.7 Захоплення і накладка (v1)

- Трейт `Capture`: `freeze_display(id) -> Frame(FP16 або RGBA8 + колірний простір)`,
  `capture_window(id)`, `list_windows()`, `list_displays()`; синтетична реалізація для тестів.
- Windows: WGC для вікна й дисплея (`R16G16B16A16Float` на HDR-дисплеях, `Borderless` через
  `RequestAccessAsync`, `IsCursorCaptureEnabled=false`), DXGI Desktop Duplication — альтернатива для
  дисплея; тон-мапінг у WGSL (формули LH: scRGB/PQ, біле SDR через `DisplayConfigGetDeviceInfo`
  тип 11, запас 200 ніт). Межі вікна — `DWMWA_EXTENDED_FRAME_BOUNDS`.
- macOS: `SCScreenshotManager` для стоп-кадру дисплея/вікна; `SCContentSharingPicker` як
  альтернативний шлях без дозволу; EDR → SDR тон-мапінг тим самим шейдером.
- Накладка: власне вікно Slint без рамки на весь монітор поверх замороженого кадру; логіка LH
  (жести «що × куди», підказки, підсвітка вікна, лупа ×4/×8/×16, відлік 3-2-1, Esc/правий клік);
  вікна накладки виключені з захоплення (`WDA_EXCLUDEFROMCAPTURE`, `NSWindow.sharingType = .none`).
- Плашка-прев'ю після знімка: кут монітора, кілька секунд, дії «Редагувати / Поділитися /
  Зберегти / Передати агенту / Закрити»; знімок уже в буфері й бібліотеці.

### 5.8 Редактор (v1)

- Вікно Slint: заголовок, рейка інструментів, смуга властивостей, полотно (Image з wgpu-текстури
  + `TouchArea`), права панель (Властивості / Метадані / Позначки), рядок стану; бібліотека —
  панель поверх полотна; налаштування — сторінка всередині головного вікна.
- Полотно: сцена Vello з документа (масштаб перегляду) + шар ручок і виділення; введення
  тексту — Slint `TextInput` поверх полотна; ефекти регіонів (Hide) — compute-проходи над «тим, що
  нижче». Експорт — та сама сцена в масштабі 1:1 (гарантія «екран = файл»).
- Інструменти й поведінка — паритет із LH (таблиця §1 `inventory_screenshots.md`), включно з
  режимом оверлея (редагування поверх екрана) і порожнім редактором з Ctrl+V.
- **Стабільна розкладка з v1 (рішення власника 28.09):** усі заплановані інструменти й елементи
  головного інтерфейсу, видимі у вікнах першого релізу, присутні на своїх місцях уже в v1; те, що
  ще не реалізовано, вимкнене (сіре, без hover) з підказкою «В розробці». Поява елементів у
  наступних релізах не має ламати верстку й звичку до розташування.
- Кілька документів: `App { sessions: Vec<Session> }` з першого дня; UI v1 — одне вікно з одним
  документом, вкладки/вікна — окремий тікет пізніше.
- Теми світла/темна; клавіатурні скорочення LH зі згадкою про Cmd на Mac.

### 5.9 Агенти (v1)

- **Режими бінарника:** `znimok` (GUI), `znimok <підкоманда>` (CLI: capture, annotate, export,
  library, ocr, windows, mcp), `znimok mcp` (stdio MCP-сервер).
- **IPC:** JSON-RPC 2.0 по рядках через named pipe (Windows, DACL лише поточний користувач) або
  Unix-socket (macOS, 0600) + токен сесії з профілю; ті самі `Command`/`Query`. Якщо GUI не
  запущено — CLI/MCP працюють headless для всього, крім захоплення на macOS (дозвіл TCC належить
  GUI-застосунку) → запускають GUI у фоновому режимі.
- **MCP-інструменти v1:** `list_displays`, `list_windows`, `capture_screen`, `capture_window`,
  `capture_region`, `annotate` (масив об'єктів у координатах знімка або за id вікна: «виділи вікно
  провідника»), `export`, `library_search`, `library_get`, `ocr`, `redact_pii`; ресурси — елементи
  бібліотеки. Зображення повертаються як image content, зменшені до ліміту клієнта, оригінал —
  `resource_link`.
- **Дозволи:** перше звернення клієнта → діалог у GUI «дозволити агенту X знімати екран?» (цей раз /
  ця сесія / завжди); області: знімок, читання бібліотеки, запис у бібліотеку, налаштування;
  видимий індикатор під час дій агента (трей + плашка), журнал дій у профілі, «відкликати всіх».
- **Продукт → агенти:** шар провайдерів `ModelProvider` (OnDevice: OCR/обличчя; Anthropic BYOK);
  «Передати агенту» — файл + JSON-контекст (вікно, програма, OCR-текст) у Claude Code
  (`claude` CLI з підготовленим промптом) або копія в буфер для інших; розумне маскування — OCR на
  пристрої + шаблони секретів/PII, обличчя (Apple Vision; Windows — пізніше через ONNX) →
  пропозиція об'єктів Hide; помічник природною мовою — запити до BYOK-моделі з описом інструментів
  = ті самі команди. Хмара вимкнена без ключа; режим на функцію; попередній перегляд відправки.
- **Помічник Ctrl+K (рішення власника 28.09):** поточний Sonnet типово (Sonnet 5.5 з 29.09), Opus 5.5 у налаштуваннях; без
  підтвердження в хмару йде лише текст команди + структура документа без пікселів; зображення — після
  локального OCR/маскування і діалогу «Надіслати знімок?» з прев'ю та чекбоксами «не питати для цього
  документа» / «не питати більше»; перша хмарна дія — діалог з поясненням, що платне і скільки коштує
  (без прихованого ліміту, лічильник у «Агентах»); ключ у Credential Manager / Keychain (env
  `ANTHROPIC_API_KEY` для розробки); дозволено правки документа (кожна = крок undo) + експорт/копіювання
  з підтвердженням, видалення — ні; без ключа/офлайн Ctrl+K — локальна командна палітра (команди,
  налаштування, маскування, OCR-пошук) з позначеними хмарними пунктами; журнал 90 днів без зображень
  (час, команда, чи був знімок, токени, оцінка вартості), спільний з MCP-агентами, експорт CSV.
- **Дистрибуція для агентів:** `.mcpb`-бандл для Claude Desktop, `claude mcp add` у документації,
  `SKILL.md`, `AGENTS.md`, `llms.txt`.

### 5.10 Безпека й довіра

- `asInvoker`, per-user інсталяція без UAC; жодного мережевого доступу, крім перевірки оновлень
  (GitHub Releases) і явних дій користувача (BYOK, майбутні інтеграції).
- Оновлення: Windows — власний оновлювач: GitHub Releases → ECDSA P-256-перевірка пакета (ключ у CI-секреті, публічний у коді) → тихий `msiexec`; macOS — Sparkle з ключем EdDSA (другий ключ підпису, теж у CI-секреті; ротація обох — ZK-111), вікно оновлення наше;
  `verify_release` поза продуктом як частина чек-листа.
- Підпис: Authenticode (Certum) і Developer ID + hardened runtime + нотаризація — окремі тікети,
  вмикаються, коли є сертифікати; до того — тестові збірки (на Mac ad-hoc підпис локально).
- CI: `cargo-deny` (ліцензії: заборона GPL/AGPL; advisories), `cargo-audit`, `cargo-auditable`,
  SBOM CycloneDX у реліз, `cargo-vet`, закріплені версії, відтворювані збірки.
- Парсери формату й імпортерів — `cargo-fuzz`, межі розмірів, перевірка довжин.
- IPC/MCP: автентифікація токеном, без відкритих портів; розширення браузера (v2) — Native
  Messaging, публікація в Chrome Web Store.
- Документ загроз `docs/threat-model.md` і політика приватності — у Фазі 7.

### 5.11 Локалізація, доступність, тестування

- Мови (рішення власника 28.09): українська й англійська — завжди і повні; мова інтерфейсу = мова
  системи, будь-яка інша → англійська; кожен відсутній рядок падає на англійську. **Еталон — файли
  мови, зручні для ШІ:** `i18n/en.ftl` і `i18n/uk.ftl` (Fluent: коментарі, контекст, змінні, множина),
  де кожне повідомлення має коментар-інструкцію для перекладача-ШІ: де показується (екран, елемент),
  тип (кнопка в наказовому способі, заголовок, підказка, повідомлення про помилку), обмеження довжини,
  значення змінних, тон; на початку файлу — глосарій термінів Znimok і правила. `i18n/README.md` —
  покрокова інструкція для ШІ «як додати мову». Slint отримує переклади похідно: збірка генерує з
  `.ftl` файли `.po` для `@tr` (або майбутній `Translator`); ядро, CLI і MCP читають ті самі `.ftl`
  через `fluent-rs`. Перевірка в CI: повнота обох еталонів, збіг змінних, довжини, множинні форми
  (українська має три). Нова мова = один файл `xx.ftl` від ШІ + автоматична перевірка; у меню мов
  показуються лише повні переклади.
- Доступність: AccessKit через Slint; клавіатурна навігація редактора.
- Тести: юніт (core/format/render на CPU), golden-зображення рендера (власні еталонні сцени з усіма
  видами позначок; еталони затверджуються очима, далі порівнюються піксельно в допуску), e2e через
  шар команд на обох ОС у CI із синтетичним джерелом кадрів (номер кадру «впечений» у кадр, як у
  LH), тести UI через тестовий бекенд Slint, fuzz парсерів; для v2 — порт `vidcheck`/`evprobe`
  у Rust і перевірка звіту через headless Chrome.

## 8. Що потрібно від власника

5. **Перевірки:** після кожного прототипу й наприкінці кожної фази — жива перевірка на Windows і
