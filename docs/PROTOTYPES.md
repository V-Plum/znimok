# Звіт по прототипах Фази 1 (ZK-18)

Підсумок чотирьох прототипів зняття ризиків (ZK-14…17) і рішення, які з них випливають.
Виміри — з тікетів і живих перевірок власника 28.09.2026; подробиці — у коментарях тікетів.

## Коротко

| Питання | Рішення | Підстава |
|---|---|---|
| Оболонка UI: Slint чи egui | **Slint** — підтверджено, egui як запасний план знято | Робочий застосунок `znimok-app` на Slint на обох ОС: бібліотека, редактор, накладка, налаштування, провідник; затримка полотна в межах критерію; 168 перевірок самотесту на тестовому бекенді Slint |
| 2D-рендер: Vello чи власні шейдери | **Vello**: `vello_cpu` — зараз і для полотна, і для експорту; GPU-шлях — окремо (ZK-130) | Критерій затримки P1 виконано на CPU-шляху; `vello` 0.10 тягне wgpu 29, а Slint — wgpu 30, тож спільний `Device` поки неможливий без форку |
| Оновлення: Velopack чи Sparkle | **Знято рішеннями власника 28.09**: Windows — `.msi` + власний оновлювач; macOS — Sparkle з власним вікном | Рішення 30 і 33 у PLAN.md §2 |
| Захоплення Windows | **WGC** основний шлях, DXGI DD — запасний | P2: HDR FP16 → тон-мапінг за формулами LH збігається з LH на 99,99 % пікселів (±2) |
| Захоплення macOS | **SCScreenshotManager з дозволом** — основний; пікер без дозволу — лише запасний | P3: пікер працює тільки через кадр SCStream, і macOS малює на ньому фіолетовий значок трансляції |
| Відтворення відео без копіювання | **Так, на wgpu 30 без патчів** (DX12 і Metal) | P4: 4K60 з запасом; перемотка ≤ 100 мс при GOP ≈ 0,25 с на обох ОС |

## P1 — полотно (ZK-14)

- Документ зі всіма видами позначок рендериться `vello_cpu` + Parley у текстуру wgpu, яку Slint
  показує як `Image`; ручки, виділення, текст поверх полотна, експорт 1:1 — працюють.
- Затримка «подія → кадр» на моніторі власника (3840×2160 @ 120 Гц, HDR, RTX 4080): **7,7 мс у вікні**
  (p50, менше одного кадру 8,33 мс), 9,4 мс на весь екран; CPU 1–2 мс. Критерій ≤ 8 мс у вікні —
  виконано.
- Рендер вивірено з LH за кодом і знімками LH (пікселізація, розмиття, наконечники, контури,
  пунктир, олівець-сплайн, лічильники, штампи, тінь і сяйво) — коміт `9953529`.
- Еталонні тести рендера (golden, ZK-114) і знімки інтерфейсу в обох темах (ZK-117) стоять у CI.
- **Не зроблено:** GPU-шлях `vello` і часткове перемальовування — ZK-130 (поліпшення, не блокер).

## P2 — захоплення Windows (ZK-15)

- WGC `Borderless` з процесу `asInvoker` — без жовтої рамки на 26100+; перший кадр 5–9 мс.
- HDR: WGC і DXGI віддають FP16 (scRGB); тон-мапінг 4K ≈ 26–33 мс; порівняння з LH — mean 0,02,
  99,99 % пікселів у ±2.
- Координати вікон через `DWMWA_EXTENDED_FRAME_BOUNDS` точні на масштабі 150 %.
- Змішаний DPI двох моніторів — ZK-36 (Done без живої перевірки; накладка на всіх дисплеях — ZK-139).

## P3 — захоплення macOS (ZK-16)

- SCK стоп-кадр після дозволу «Запис екрана»: 3600×2338 (Retina), знімок ≈ 170 мс.
- Провідник дозволів (TCC), гарячі клавіші через Carbon без дозволів, трей, автозапуск
  SMAppService, сталий самопідписаний сертифікат (дозвіл переживає перезбирання), CI macos-26.
- Пікер `SCContentSharingPicker` без дозволу: `SCScreenshotManager` відмовляє навіть із фільтром
  пікера; працює лише один кадр `SCStream` (≈ 240 мс), і на ньому значок трансляції → **запасний
  шлях** (ZK-129).
- Додаткове системне вікно macOS 15+ про «обхід системного пікера» — одноразове, провідник має
  про нього попереджати.

## P4 — відтворення без копіювання (ZK-17)

| | Windows (UHD 630) | macOS (M1 Pro) | Критерій |
|---|---|---|---|
| 4K60 без копіювання | 113 к/с | 560–610 к/с | ≥ 60 |
| CPU при 60 к/с | 0,4 % | 1,9 % | ≤ 10 % |
| Перемотка (GOP 15) | ≤ 61 мс | медіана 26, макс 50 мс | ≤ 100 мс |
| Запасний шлях через CPU | працює | 536 к/с | працює |

- Висновок для запису (ZK-87/88): кодувати з GOP ≈ 0,25 с — тоді перемотка вкладається в 100 мс.
- Знахідка: AVAssetReader штампує кадр, що покриває початок діапазону, часом початку — діапазон
  починати на 0,1 кадру всередині потрібного.
